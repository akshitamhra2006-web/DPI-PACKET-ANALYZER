## 2. Quantitative Flow Feature Space (24 Features — Schema 2.0.0)

The pipeline transforms variable-length bidirectional packet captures into a fixed 24-dimensional feature vector under Schema 2.0.0. Raw `destination_port` and raw `protocol_num` are banned to prevent artificial port memorization:

| Index | Feature Name | Data Type | Units / Range | Security Rationale |
| :---: | :--- | :--- | :--- | :--- |
| **0** | `duration_seconds` | `float64` | $[0.0, \infty)$ s | Short bursts characterize port scans; long sessions characterize tunnels or C2. |
| **1** | `total_packets` | `float64` | $[1.0, \infty)$ | Volume metric; distinguishes single-probe scans from bulk transfers. |
| **2** | `total_bytes` | `float64` | $[0.0, \infty)$ bytes | Identifies exfiltration or high-volume downloads. |
| **3** | `packets_per_second` | `float64` | $[0.0, \infty)$ pkts/s | Flood and burst identification. |
| **4** | `bytes_per_second` | `float64` | $[0.0, \infty)$ B/s | Throughput rate per second. |
| **5** | `byte_asymmetry_ratio`| `float64` | $[0.0, \infty)$ | Exfiltration shows high ratio; clean web traffic shows balanced or low ratio. |
| **6** | `packet_asymmetry_ratio`| `float64` | $[0.0, \infty)$ | Unidirectional scanning yields high asymmetry; bidirectional sessions $\approx 1.0$. |
| **7** | `fwd_packets` | `float64` | $[0.0, \infty)$ | Outbound packet count from initiator. |
| **8** | `fwd_bytes` | `float64` | $[0.0, \infty)$ bytes | Outbound payload and header volume. |
| **9** | `rev_packets` | `float64` | $[0.0, \infty)$ | Inbound packet response count. |
| **10**| `rev_bytes` | `float64` | $[0.0, \infty)$ bytes | Inbound payload and header volume. |
| **11**| `pkt_size_min` | `float64` | $[0.0, \infty)$ bytes | Minimum packet size in flow. |
| **12**| `pkt_size_max` | `float64` | $[0.0, \infty)$ bytes | Maximum packet size in flow. |
| **13**| `pkt_size_mean` | `float64` | $[0.0, \infty)$ bytes | Average packet size in flow. |
| **14**| `pkt_size_stddev` | `float64` | $[0.0, \infty)$ bytes | Dispersion of packet sizes. |
| **15**| `iat_mean` | `float64` | $[0.0, \infty)$ $\mu$s | Average inter-arrival time between packets. |
| **16**| `iat_stddev` | `float64` | $[0.0, \infty)$ $\mu$s | Jitter in inter-arrival time. Low variance indicates automated beaconing. |
| **17**| `fwd_syn_count` | `float64` | $[0.0, \infty)$ | SYN sweep detection in forward direction. |
| **18**| `fwd_ack_count` | `float64` | $[0.0, \infty)$ | Handshake and acknowledgment tracking. |
| **19**| `fwd_fin_count` | `float64` | $[0.0, \infty)$ | Graceful teardown monitoring. |
| **20**| `fwd_rst_count` | `float64` | $[0.0, \infty)$ | Abrupt connection resets or scanning responses. |
| **21**| `fwd_psh_count` | `float64` | $[0.0, \infty)$ | Interactive application data pushes. |
| **22**| `is_well_known_port`| `float64` | $\{0.0, 1.0\}$ | $1.0$ if destination port $< 1024$. |
| **23**| `is_ephemeral_port` | `float64` | $\{0.0, 1.0\}$ | $1.0$ if destination port $\ge 49152$. |

## 3. Preprocessing, Imputation & Safety Bounds

To ensure robust numerical stability and guard against adversarial numerical overflow, `FeaturePipeline` applies multi-stage sanitization:

```python
from ml.feature_pipeline import FeaturePipeline

pipeline = FeaturePipeline(scale=True)
X, feature_names = pipeline.fit_transform(flows)
```

### Safety Rules Implemented:
1. **Division-by-Zero Protection**: Ratios such as `bytes_per_packet` use $\max(\text{total\_packets}, 1)$. `fwd_rev_packet_ratio` uses Laplace smoothing: $\text{fwd\_packets} / (\text{rev\_packets} + 1)$.
2. **Missing Key Defaults**: If a flow record lacks TCP flags (e.g., pure UDP or ICMP flows), all TCP flag metrics default safely to $0.0$.
3. **Data Leakage Immunity**: Identifiers (`flow_id`), source/destination IP strings, port numbers (except boolean binning), and payload byte strings are strictly omitted from $\mathbf{X}$.
4. **Finite Bound Enforcement**: Any `NaN` or `Inf` generated by downstream mathematical edge cases is replaced with $0.0$ and clipped to $[-10^9, 10^9]$.

## 4. Supervised Model Training Workflow

The supervised model categorizes flows into five distinct threat and traffic classes:
`BENIGN`, `PORT_SCAN`, `C2_BEACON`, `DNS_TUNNEL`, `MALWARE_HTTP`.

### Step 1: Dataset Extraction & Preparation
Extract genuine flow records from PCAP captures or load a labeled JSON dataset:
```python
from ml.dataset_manager import DatasetManager

# Generate or load labeled flows
dataset_info = DatasetManager.generate_flow_dataset()
flows = dataset_info["flows"]
labels = dataset_info["labels"]
```

### Step 2: Training the Primary Classifier (`RandomForestClassifier`)
```python
from ml.models import SupervisedIDSModel

# Initialize model
rf_model = SupervisedIDSModel(model_name="NIDS-RandomForest", algorithm="RandomForestClassifier")

# Train with 100 estimators and balanced class weights
rf_model.train(
    flows=flows,
    labels=labels,
    n_estimators=100,
    max_depth=12,
    class_weight="balanced",
    random_state=42
)
```

### Step 3: Training the High-Throughput Classifier (`HistGradientBoostingClassifier`)
```python
hgb_model = SupervisedIDSModel(model_name="NIDS-HistGradientBoosting", algorithm="HistGradientBoostingClassifier")

hgb_model.train(
    flows=flows,
    labels=labels,
    max_iter=100,
    max_leaf_nodes=31,
    learning_rate=0.1,
    random_state=42
)
```

### Step 4: Stratified Cross-Validation Evaluation
To prevent optimistic bias from resubstitution evaluation, all models are evaluated using Stratified Cross-Validation:
```python
from ml.experiment_framework import ExperimentRunner

runner = ExperimentRunner(experiment_id="EXP-EVAL-01")
cv_results = runner.evaluate_cross_validation(
    model_class=SupervisedIDSModel,
    model_init_kwargs={"model_name": "NIDS-RandomForest", "version": "2.0.0"},
    X=X,
    y=y,
    classes=["BENIGN", "PORT_SCAN", "C2_BEACON", "DNS_TUNNEL", "MALWARE_HTTP"],
    n_splits=5
)

print(f"CV Accuracy: {cv_results['metrics']['accuracy']:.4f} +/- {cv_results['metrics']['accuracy_std']:.4f}")
print(f"CV Macro-F1: {cv_results['metrics']['f1_macro']:.4f} +/- {cv_results['metrics']['f1_macro_std']:.4f}")
```

## 5. Unsupervised Anomaly Detection Training Workflow

The anomaly detector flags novel or out-of-distribution traffic without requiring pre-labeled attack data.

```python
from ml.anomaly_detector import UnsupervisedAnomalyDetector, MIN_BASELINE_SAMPLES

# Extract verified baseline clean/legitimate flows
normal_flows = [f for f, l in zip(flows, labels) if l == "BENIGN"]

detector = UnsupervisedAnomalyDetector(
    model_name="FlowAnomaly-IsolationForest",
    version="2.0.0",
    contamination=0.05,
    threshold=0.65,
    min_baseline_samples=MIN_BASELINE_SAMPLES
)

# Minimum sample constraint: requires >= 10 normal flows
if len(normal_flows) >= MIN_BASELINE_SAMPLES:
    detector.fit_baseline(normal_flows, dataset_name="PCAP Benign Baseline")
    detector.save("models/anomaly")
else:
    print(f"Insufficient baseline traffic ({len(normal_flows)} < {MIN_BASELINE_SAMPLES}). Marked INSUFFICIENT_BASELINE_DATA.")
```
